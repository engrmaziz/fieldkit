## 1. Overview & Architecture

Project 1 (Mini Foundry) solves Halden Industrie's core data fragmentation challenge: four heterogeneous source systems (ERP Latin-1, Plant Excel sheets, Legacy SOAP portal, and GLEIF authoritative data) represent the same supplier and supply chain entities with conflicting names, typos, and schema drifts.

## 2. Failure Modes & Mitigations (Mandatory Handling)

All six critical failure modes defined in the roadmap are actively handled, mitigated, and verified with automated test suites:

| # | Failure Mode | Root Cause | System Mitigation | Test Suite Verification |
| :- | :--- | :--- | :--- | :--- |
| **1** | **SOAP Portal Down Mid-Run** | Legacy SOAP supplier service crashes or times out during scheduled batch run. | Circuit breaker opens after 3 consecutive failures; pipeline marks run as `partial`; healthy sources (ERP CSV, Excel, GLEIF) continue promotion without halting; critical alert emitted. | `services/ingest-workers/tests/test_soap_connector.py::test_circuit_breaker_opens_after_failures` |
| **2** | **Encoding Mis-detected** | German ERP export file provided in Windows Latin-1 (`iso-8859-1`) or CP1252 instead of UTF-8. | Data contract validation inspects byte headers and verifies umlauts (`ä, ö, ü, ß`) against check columns. Corrupt or unparseable files are quarantined to `data/quarantine/` with zero database corruption. | `services/ingest-workers/tests/test_contracts.py::test_contract_validation_and_quarantine`, `test_csv_connector.py::test_latin1_umlaut_roundtrip` |
| **3** | **Excel Template Changed by Planner** | Plant planner renames or drops a critical header (e.g. `bestelldatum` $\to$ `order_date`). | Statistical fingerprinting triggers schema drift rule with severity `BLOCK`. Staging promotion halts for that file; LLM generates column rename suggestion; mapping is reviewed in Drift Inbox and stored in `contract_override`. | `services/ingest-workers/tests/test_drift.py::test_drift_rule_column_removed_and_added`, `test_drift_rule_with_active_override` |
| **4** | **ER Over-Merge (False Positive Cluster)** | Two distinct corporate entities with similar names erroneously clustered together. | Human operator marks pair as `non_match` via Console UI (`m/n/s` hotkeys). Review API executes cluster split in a single database transaction, re-pointing downstream links and appending an immutable audit trail. | `services/foundry-api/tests/test_review_queue.py::test_review_queue_lifecycle` |
| **5** | **LLM Unavailable / Offline** | Local Ollama daemon unreachable, timed out, or overloaded during grey-zone adjudication. | System skips automatic adjudication without guessing; ambiguous candidate pairs route directly to human review queue (`review_queue` table). Zero hallucinated entities promoted. | `packages/er/tests/test_adjudicator.py::test_adjudicator_low_confidence_routes_to_review_queue` |
| **6** | **Promotion Crash Midway** | Database connection lost or host power failure occurs during multi-table ontology promotion. | Promotion runs inside an atomic SQLAlchemy 2 / PostgreSQL transaction block (`async with session.begin()`). Rollback triggers on error, ensuring zero partially promoted rows or orphaned links. | `packages/ontology/tests/test_promote.py::test_idempotent_promotion_and_provenance` |
